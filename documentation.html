Wenine Hours

A web application for tracking, planning and approving internship (stage) hours at Wenine — built with HTML, CSS and JavaScript on a Firebase cloud database.

1Problem & goal

Interns at Wenine must prove a fixed number of internship hours (for example 1000 hours) before a deadline. Hours were kept in a shared spreadsheet: error-prone, not accessible on a phone, no automatic calculation of the special rules (the company is closed on Mondays; weekend hours count double), and no way for a supervisor to formally approve hours.

Goal: one small web app where every intern logs hours on their own calendar, totals and weekly sums are calculated automatically with the company rules applied, a planner predicts whether the required hours will be reached before the deadline, and an admin reviews, corrects and confirms the hours — after which they are locked.

2User stories

As an intern (student)

US-01 · logging hours
As an intern, I want to enter the time I started and stopped, so that my hours are calculated for me.
  • Entering “from” and “to” fills in the hours automatically (overnight shifts handled).
  • I can also type the hours directly.
US-02 · day status & notes
As an intern, I want to mark a day as worked or free and add a note, so that my calendar explains itself later.
  • Each day has a Worked/Free choice at the top of the editor and a free-text note.
US-03 · company rules are automatic
As an intern, I want the company rules applied for me, so that I cannot make rule mistakes.
  • Mondays are automatically crossed out (“Closed”) and cannot be filled in.
  • Saturday and Sunday hours count double (×2) in every total.
US-04 · overview of my progress
As an intern, I want weekly and total counters, so that I always know where I stand.
  • Every calendar week row ends in a week total; the top of the page shows total counted hours, real hours, weekend bonus and days worked.
US-05 · two ways of working
As an intern, I want to switch between a calendar and a compact spreadsheet-style list, so that I can use whichever is faster.
  • In the list view I type directly into the cells (hours, times, note) and rows save themselves.
  • Typing a word like “vrij” or “ziek” in the hours column marks the day as not worked, like on the old paper sheet.
US-06 · planner
As an intern, I want to enter how many hours I need, which days I can work and until when, so that I know if I will reach my hours on time.
  • The planner shows a clear verdict (“you make it around <date>” / “you are X hours short”), a progress bar, my weekly pace vs. the needed pace, and a month-by-month projection.
  • It respects the rules: Mondays closed, weekends ×2, already-filled days not counted twice.
US-07 · language
As an intern, I want the app in Dutch or English, so that everyone at Wenine can use it.
  • A language switch (EN/NL) translates every text and is remembered.
US-08 · any device
As an intern, I want to use the app on my phone, so that I can log hours right after a shift.
  • The layout adapts to small screens; data is stored in the cloud so every device shows the same hours.

As any team member (viewer)

US-09 · shared schedule
As a team member, I want one shared schedule showing who works when, so that everyone knows the planning.
  • The schedule page shows all names per day (working with times, or free). Everyone can view it; only the admin can change it.

As the admin (supervisor)

US-10 · secure admin access
As the admin, I want to log in with an email and password, so that only I can manage the system.
  • Login uses Firebase Authentication; the database itself refuses protected writes from anyone not logged in.
US-11 · manage people
As the admin, I want to add people and set from which date until which date they can work, so that each intern gets their own calendar for their own period.
  • Add/edit/remove person is only visible — and only allowed by the database — for the admin.
US-12 · check all hours in one place
As the admin, I want a dashboard with every person’s hours side by side per month, so that checking is fast.
  • Rows are days, columns are people; each cell shows hours, times and markers; totals per person per month at the bottom.
US-13 · confirm and lock
As the admin, I want to confirm correct hours, so that they can never be changed afterwards.
  • A confirmed day shows a green ✓ everywhere and is locked for everyone except the admin — enforced by database security rules, not only by the interface.
  • A “Confirm month” button confirms all filled days of a month at once.
US-14 · transparent corrections
As the admin, I want my corrections to be visible to the intern, so that changes are never silent.
  • A day changed by the admin shows a ✎ “changed by admin” marker on the intern’s calendar, list and day editor.

6Architecture & data model

Plain HTML/CSS/JavaScript, no frameworks. Hosting is static (GitHub Pages); all data lives in Google Firebase: Cloud Firestore for storage with live synchronization, Firebase Authentication for the admin login. One shared translation module (i18n.js) serves all pages.

7Security

The admin logs in with email + password (Firebase Authentication). Permissions are enforced inside the database by Firestore security rules, so they hold even if someone bypasses the interface:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /people/{id}   { allow read: if true; allow write: if request.auth != null; }
    match /schedule/{id} { allow read: if true; allow write: if request.auth != null; }
    match /planner/{id}  { allow read, write: if true; }
    match /entries/{id} {
      allow read: if true;
      allow write: if request.auth != null;          // admin: everything
      allow create: if request.resource.data.confirmed != true
                    && request.resource.data.editedByAdmin != true;
      allow update: if resource.data.confirmed != true
                    && request.resource.data.confirmed != true
                    && request.resource.data.editedByAdmin != true;
      allow delete: if resource.data.confirmed != true;
    }
  }
}

In words: everyone can read; interns can only write unconfirmed hour entries and can never set the “confirmed” or “changed by admin” stamps themselves; people and the schedule are admin-only; once confirmed, an entry can only be touched by the admin.

8Example calculation (the planner)

Target 1000 hours, deadline 30 April, available Tuesday–Friday, 8 hours per day. The planner walks every remaining day to the deadline (skipping Mondays and already-filled days, counting weekends double) and concludes: 968 of 1000 hours — 32 short. Adding one Saturday (8 real hours = 16 counted) flips the verdict:

You make it: with this plan you reach 1000 h around mid-April — with room to spare before 30 Apr 2027. ✓

9Possible next steps

Print/PDF export of the month sheets for the school file · a personal login per intern · e-mail reminder when a week has no hours · export to Excel. The architecture (separate pages on one shared database with rule-based permissions) supports all of these without redesign.
